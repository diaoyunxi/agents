# 工具 `stop` —— 请求结束当前任务（信号工具）

## 作用

这是一个**控制型工具**，不执行任何文件/命令副作用。AI 在判断「任务确实已完成，无需再调用任何工具」时，显式调用 `stop` 来结束本轮任务。

## 行为约定

- 一旦 AI 在某一轮里调用了 `stop`，同一轮中其后的工具调用会被忽略，运行时**立即**停止后续的工具交互轮次，并正常收尾。
- 如果 AI **没有**调用任何工具（既没调用工作工具，也没调用 `stop`），运行时会**不结束**，而是回灌一条指令要求 AI 继续推进；连续 3 轮都不调用任何工具才会强制结束，避免死循环。
- `stop` 不受工具调用次数上限与允许/禁用列表约束，始终可调用（它本身也不计入调用次数）。
- 因此：`stop` 是 AI 主动结束任务的**唯一显式信号**；不写工具调用则默认被视为「任务尚未完成，请继续」。

## 参数

- `reason`（string，可选）：停止原因或一句话总结，会被回显，帮助用户了解为何停止。

## 输出格式

最终答复写完后，再单独输出这一个 JSON，且本轮不要再有其它工具调用：

```
{"tool": "stop", "arguments": {"reason": "已完成 README 更新"}}
```

## 使用场景

- 任务已全部完成，给出最终总结后调用 `stop` 结束。
- 用户明确说「不用做了 / 到此为止」时调用 `stop`。

## 注意事项

- 不要为了「省步骤」而滥用 `stop`；只要还有可推进的工作，就应继续调用相应工具。
- 不要只写一段结论文本就停下，必须显式调用 `stop`，否则会被运行时要求继续。
