# 新功能开发流程

实现新功能时严格按以下顺序推进，不要跳步。

1. 理解现状：先用 `list_dir` 看清相关目录，用 `search_files` 找到同类实现作为参考。
2. 说明计划：用 3 到 5 条中文要点告诉用户你准备改哪些文件、为什么。
3. 小步实现：每次 `edit_file` 只改一个逻辑点，改完立刻读文件或跑命令验证语法。
4. 验证：运行测试或最小可执行片段，失败则根据报错回到第 3 步。
5. 收尾：用中文 Markdown 总结新增或修改了哪些文件、如何使用、有哪些已知限制。

## 约束

- 不要臆造依赖，新增第三方库前先确认 requirements.txt 中是否已有。
- 不要删除用户已有代码，废弃逻辑用注释标注原因。
- 公共函数要有类型标注与简短说明。
