# Brand Guidelines

Make any user-facing asset comply with the project's brand identity.

## When to use
- Creating slides, documents, UI, or graphics that must look on-brand.

## Steps
1. **Load the brand tokens**
   - If the project has brand docs, a design system, or tokens file, use them.
   - Otherwise establish (or ask for) the core set:
     - Primary brand color(s) and their roles.
     - Neutral scale (text, backgrounds, borders).
     - 1-2 typefaces: display/heading + body, with sizes and weights.
     - Logo usage (clear space, min size, do-nots).
2. **Accent-rotation rule** — When many sections/cards need color, rotate through the accent palette in a fixed order rather than picking randomly. This keeps variety controlled and on-brand.
3. **Apply consistently**
   - Headings use the display font; body uses the body font.
   - Color roles are semantic (primary = brand action; success/warn/error = status; neutrals = structure).
   - Spacing and margin rhythm match the brand.
4. **Verify** — Check for off-palette colors, wrong font, logo misuse (stretching, recoloring, clipping clear space), and contrast issues.

## Rules
- Never invent brand elements the user hasn't defined; if unknown, ask or use the existing tokens.
- Keep the logo intact; do not add effects, shadows, or recolor outside the brand's allowed variants.
- Prefer restraint: a strong brand uses few colors, not many.

## Stop conditions
- The asset uses only approved tokens, the logo is used correctly, and contrast passes → stop.
