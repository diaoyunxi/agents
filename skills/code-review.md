# 代码审查流程

1. 先用 `list_dir` 与 `search_files` 圈定审查范围，用 `read_file` 读取关键文件全文。
2. 按下面的维度逐项检查，并在结论中标注文件路径与行号：
   - 正确性：边界条件、空值、异常处理、并发与资源释放
   - 安全：命令注入、路径穿越、密钥硬编码、越权
   - 结构：职责划分、重复代码、命名与类型标注
   - 性能：不必要的循环嵌套 IO、重复请求、可缓存的昂贵计算
3. 问题按「阻断 / 重要 / 建议」三级分类，每条给出问题、影响与最小改法。
4. 若需要改动，先征得用户同意，再用 `edit_file` 落地，每轮改动后说明验证方式。

## 输出格式

- 一段不超过 5 行的总体结论
- 三级分类的问题列表
- 一个可执行的改进顺序建议
